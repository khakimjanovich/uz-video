What happens when a merchant's server asks for the same payment twice? The server sends create payment, the network hiccups, and no answer comes back. So it sends the same request again. Without care, the buyer gets two payment pages, and may pay twice. Think of a lift button: press it once or ten times, and one lift comes. So each create carries an idempotency key: the merchant's own name for this attempt. The same key with the same request gets the first answer back, marked as a replay. The same key with a different request is refused, because it is a different request under an old name. And two retries arriving at the very same moment meet at one place: one wins, and the other gets the winner's answer. Press as often as you like, and one payment comes.
