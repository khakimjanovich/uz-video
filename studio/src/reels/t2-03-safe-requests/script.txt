How does the bank know a payment request really came from the store, and only once? The simplest way is to send the amount and order with the API key. But that invites a replay attack: a copied request is sent again, and a network retry can create a second payment. So every request carries an HMAC-SHA256 signature, made with the store's secret key over the request body, a timestamp and a nonce. The bank computes the same HMAC, so if anything in the request was changed, the signatures no longer match. The timestamp must fall within the configured window, and each nonce is accepted only once, which stops replays. For retries, payment requests use an idempotency key, a common pattern in payment APIs. The same key with the same request returns the first result, so no second payment is created. The same key with a different request is rejected.
