Three months ago, Aziz printed a ticket at a copy shop. He logged in to the marketplace website on the shop's computer, and he never logged out. Last week, he bought a new phone and installed the mobile bank, with a green TAF check. Today, a stranger at the copy shop opens that old browser, finds the list of sessions, and taps End on the mobile bank on Aziz's new phone. Two sessions of one person, and one wants the other gone. Which one should win? In lesson twenty-one, each session got its tokens and its level. This lesson adds two more facts to every session: when it started, and its rank. First, the rules that fail. Rule one: any session can end any other session. Then the stranger ends the owner, and keeps the door. Rule two: the older session wins. That sounds fair, but the copy-shop session is three months older than Aziz's new phone. So the stranger wins again. Age alone cannot tell the owner from the thief. Something else must count: how strongly the session was checked. That is the rank. A session has rank two when it is in the master app and its TAF verdict was green. It also has rank two when the verdict was yellow and the customer then passed MyID. When TAF was down and nothing was scored, the session has rank one, until a later green verdict raises it. Every other session has rank one: every web session, and every session in a side app. Now the rule. A session can end another session only when that session has a lower rank. Or when both have the same rank, and the other one is younger. Back to the copy shop. The stranger's session has rank one. Aziz's new phone has rank two. So the platform refuses, and writes an audit event and an antifraud event. Now Aziz opens the list of sessions in the mobile bank. He sees the copy-shop browser, with its app and its start time. He taps End, and it ends, because rank two outranks rank one. Age matters only between equals. Two marketplace sessions, both rank one: the older one can end the younger one, but not the other way around. I think this is a quiet, good idea. The owner usually has the strongest check. A thief usually has the oldest forgotten door. So the rank comes first, and the age only breaks a tie. One more rule cuts deeper. A password change or a password reset ends every other session of the same or a lower rank, whatever its age. The age rule applies only when the customer ends one session from the list. Lesson thirty uses this. Each new session also sends a notification: by push to every other session, and by SMS. So no new door opens in silence. And there is a second guard: the probation period. A fresh session is the riskiest moment, even after a green TAF verdict and a MyID check. A check can be fooled once. So after a new session, a new phone, or a password reset, each app blocks some of its own actions for a while. Which actions, and for how long? The bank decides, for each app, in the platform's policies. The platform does not block those actions itself. It does not even know them. Instead, the token of each session carries four facts: when the session started, when its probation ends, its rank, and its level. The backend of each app reads them, and blocks its own risky actions until the probation ends. So the mobile bank and the marketplace can each be careful in their own way, with one shared truth about the session. To recap: every session has a start time and a rank. Rank two comes from the master app, with a green verdict, or a yellow verdict and MyID. A session ends only lower ranks, or younger equals. A password change ends all same or lower ranks. And the probation slows down every new session, in each app's own way. Now picture a sharper stranger. He talked the mobile operator into a new SIM card with Aziz's number. He installs the mobile bank, and asks for a new password, as if he forgot it. Aziz still has active sessions. Should that reset happen at once? Next: the password reset.
