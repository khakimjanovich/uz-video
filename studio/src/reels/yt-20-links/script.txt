A seller on Instagram has no checkout: how do they take a card? With a payment link: the merchant's user makes it in the portal, and sends it to the buyer in any chat. Behind the link is an ordinary payment, with the same bank page, the same code, and the same debit. It has no API client and no return address, and its order number is made up, starting with link. Only the owner makes one, and only for a live website: anything else gets the same refusal. The merchant chooses how long it works, up to the bank's configured limit, seven days. The link carries a random token, shown once, and the bank keeps only its hash, so a leaked table opens no page. The buyer opens it, enters the card and the code, and the page says paid, with no shop to go back to. Pages nobody pays in time, links and checkouts alike, are closed by a sweep every minute. It locks expired rows with skip locked, so each one closes once, however many instances run it. Expired is final, and like every ending it raises an event, so a website with a webhook hears about it. In the portal, the merchant sees each link's status: waiting, paid, or expired. Next, sending money back: refunds and reversals.
