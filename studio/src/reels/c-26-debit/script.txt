How do you make sure a card is charged exactly once? The buyer clicks pay twice, or the page retries, or two copies of the app handle the same confirmation. Each of them would charge the card. And if the app crashes after asking the network, but before saving the answer, nobody knows whether money moved. A bank's cash desk solves both problems. Only one cashier can hold the withdrawal slip. And the cashier writes it in the logbook before opening the drawer. The debit works the same way. First comes the claim: one conditional update moves the payment from card confirmed to debiting. Only one caller's update can match, so exactly one caller wins. The winner finds the live terminal and the bank's fee. Without either, the payment fails, and nothing is charged. Then it writes a row in the operation journal, before the network is asked. The journal holds one debit per payment, and the database enforces it. ecom asks the card zone to charge the card by its token. The call carries an id that makes it happen once, even if it is sent twice. Some card networks only hold the money at first. For those, the card zone takes it at once, and that is a capture. Approved means paid, with the network's reference number. Declined is final. And no answer in time is unknown, never declined: lesson twenty-seven picks it up. Now read it in the code. The claim is a single update: set debiting, where the payment is still card confirmed. Of any number of callers, exactly one changes the row, and gets a one back. The journal table is written before every call to a network, and finished with the answer. And one unique constraint allows just one debit for each payment.
