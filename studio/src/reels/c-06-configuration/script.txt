What should a service do when a setting is missing? A good cook won't start a dish with an ingredient missing, and won't guess a pinch. Our services are the same. No setting has a default value. A guessed timeout or a forgotten password that quietly falls back to a test value is how a system goes wrong in production. So every setting comes from one locked store, Vault. What only this environment knows, like its addresses, is typed in once. Every password and key is generated there, never typed into a file. Before a service starts, it is handed exactly its own settings. If even one is missing, it refuses to start, and names every missing one at once. That is fail fast: a wrong guess can never reach production. And rates, limits and waiting times are the bank's decisions, so each one is a setting the bank chooses, never a number hidden in the product. Next: how every call proves who it comes from.
