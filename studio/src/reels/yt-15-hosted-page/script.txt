Where does the buyer type their card number: on the shop's site, or on ours? If shops collected cards, every shop would need PCI DSS, and every shop breach would leak cards. So the buyer opens the bank's own payment page through a one-time session link. The session token is stored only as a hash, and expires after the configured time. The buyer types the card, and the vault swaps it for a token at once. A one-time code goes to the card owner's phone, through the scheme or by SMS. Only one operation runs at a time per payment, thanks to a lock in Redis. Too many wrong codes or card attempts close the session. Next, the moment the money actually moves: the debit.
