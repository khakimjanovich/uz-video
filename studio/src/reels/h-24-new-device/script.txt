The box is still on the table, and the new phone smells of plastic. Aziz moves his SIM card into it and installs the mobile bank. He types his number and his password, and both are right. Isn't that enough? A stranger with a swapped SIM card and a guessed password would have exactly the same two things. In lesson twenty-three, Aziz logged in on a phone the platform already knew. This lesson starts on a phone it has never seen: the new-device code, the approval on the old phone, and the account check. The gateway checks the password first, as always. Nothing starts before a correct password. Then it looks for the device identifier, and finds nothing: this phone is not known for Aziz. So the gateway opens a new-device request. In the master app, the new-device code goes out at once. TAF sends it by SMS to Aziz's verified number. The message says it is for a login, and it names the model of the new phone. The SIM card is in the new phone, so the code lands there. That proves the SIM. It does not prove the person. Now the old phone. It is still on Aziz's desk, and it still has a session in the mobile bank. That session passed a green verdict, so it has rank two. Lesson twenty-nine explains rank. For now, rank two means a session the platform trusts to answer for Aziz. The platform sends a push signal to the old phone. The signal carries no code, only the number of the request. The old phone then pulls the request over its own session. It shows the model of the new phone, the network address, and the time. It shows a warning: never give any code to another person. And it shows two buttons: Approve, and This was not me. I think the warning matters as much as the buttons. Many thefts start with a friendly voice that asks for a code. Here, the old phone never shows a code at all, so there is nothing to read out. Aziz taps Approve on the old phone, and types the code on the new one. With a rank-two session on a different phone, the login needs both: a correct code and the approval. If the old phone stays silent for the whole approval waiting period, a correct code is enough. If no other phone has a rank-two session, a correct code is enough from the start. A session of rank one gets only a notice, without the buttons. Next comes the verdict from TAF, as in lesson twelve. Today it is green. Now the account check. The platform asks one question: what kind of account is this? If nobody used any of its devices for longer than the dormancy period, the account is dormant. Lesson thirty-two covers that. If the customer was never at level two, the login completes at level one. When an app needs more, the customer does a step-up. Aziz was at level two, so his new phone must prove his face. The mobile bank asks for consent, then runs a MyID re-check. If the reusable identifier has expired, it runs a full proofing instead. His face matches. This is the guard that a stranger cannot pass. The stranger may hold the SIM card, may know the password, and may even catch the code. But he does not have Aziz's face. Now the login completes. The platform makes a record for the new phone. It passed MyID on this device, so the state is Trusted. Without a MyID check, it would be Known. Then comes a new access grant. Last, the notice: new device login. It goes by push to Aziz's other devices, and by SMS to his number, with the model, the network address and the time. The platform writes an audit event, and sends an event to the antifraud system of the bank. And the other button? If Aziz had tapped This was not me, the login would end at once, and his number would go on hold. Lesson thirty-one shows why. One last note on side apps. On a new phone in the marketplace, the approval in the master app replaces the code. With no rank-two session, the bank's SMS service sends the code, and the session starts at level one. Lesson twenty-six covers the details. To recap. On a new phone, the number and the password are not enough. The code proves the SIM card. The old phone approves. And MyID proves the face. Now Aziz is safe from a stranger's hands. But what if a stranger guides Aziz's own hands, on a phone call, and asks him to install a screen-sharing app? Next: remote access.
