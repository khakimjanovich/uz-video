How does the bank know a payment request really came from the shop, and only once? The shop's server asks for a payment with an amount, an order number, and a return address. A stolen token alone should not be enough to create payments, so every request is also signed. The server signs the method, path, timestamp, nonce, and body with HMAC-SHA256 and the shop's secret. That secret lives in Vault under the merchants' path, so the app can read it but nobody types it. A timestamp outside the configured window is rejected, and a nonce can be used only once. A network retry must never create a second payment, so each request carries an idempotency key. The same key with the same body returns the stored response, and the same key with a different body is refused. Before saving anything, the payment module checks that the sales point is active, and refuses if it cannot tell. The response carries a one-time link to the bank's own payment page. Next, the buyer opens that page and enters their card.
