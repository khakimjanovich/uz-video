Which terminal does the processing center expect each debit to come through? It only accepts debits from terminals it already knows. So the terminal module keeps a registry: for each website and card scheme, one merchant ID and one terminal ID. Uzcard and Humo payments can use different terminals for the very same website. A terminal is registered only for a website that exists and accepts that card, and the check fails closed. The database allows one live terminal per website and card, and a merchant and terminal ID pair is never issued twice. A terminal can be suspended and resumed, and a revoked one never comes back. Every change is written to an audit log: who, what, and why. Before every debit, the payment module asks for the live terminal, and no terminal means no debit. Integration tests run on a real Postgres, with the partner module stubbed at its public interface. Under load, about forty-five hundred terminals were registered, routed and revoked in thirty seconds. Next, the card schemes themselves: talking to Uzcard and Humo.
