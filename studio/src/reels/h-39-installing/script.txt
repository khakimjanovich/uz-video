A new bank signs the contract on a Monday. Its platform team gets two empty Linux hosts: one in the test zone, and one in the production zone. What has to happen before Aziz can type his phone number for the first time? Lesson four gave the configuration, and lesson twenty-one closed the trail with the audit. Now the whole platform goes into that bank, and Aziz walks his journey one last time. Each zone gets one Linux host, and each host runs its own installation. Each unit is an image, and Docker Compose runs one copy of each image on the host. This set of units is the Compose stack. In front run the two gateways, Keycloak, the workers, and four adapters: MyID, TAF, SMS and push. Behind them run Postgres, Valkey, Kafka and Vault, and each one is new for that zone. Then OpenTofu does what lesson four showed. It gives the deploy values of the zone, and the defaults for every policy and every text. It also writes the settings and the secrets of each unit into Vault. An install script reads them from Vault and starts the stack. If one value is missing, the start stops with a clear error. Vault starts sealed: it holds the keys, but it cannot use them. It opens only with the unseal keys, and the bank's security team keeps them. So the platform team starts the stack, and the security team opens Vault. Now the stack runs, but customers still cannot come in. The installation opens for customers only when the bank has at least one active app with a required level. Here that app is the mobile bank. Until then, the platform refuses every journey. The admin panel also lists each policy and text that still has its default value, so the bank sees what it has not decided yet. Stage, in the test zone, goes first. And here is one more fact about Aziz: he is not a real person. The test team needs him every day, so in stage he is a test identity. A test identity is a record in the MyID test environment, with a known result: success, or a named failure, such as a face that does not match. Each night, the acceptance tests run in stage against these test identities. Stage connects only to the MyID test environment, and each customer that it creates carries a test mark. Limits and reports never count test customers. Production connects only to the real MyID, and there every customer is a real person, even the people that the bank uses for its own checks. No network route joins the two zones. Only configuration moves from stage to production, as a difference that a second person approves. Customers, devices, sessions and audit events never move. And production guards itself: it does not start with a test address for MyID, or when test customers are allowed. Its database refuses any customer with the test mark. Developers do not wait for a zone. The same stack runs on a laptop with one command. The simulators of lesson five play MyID, TAF, the SMS vendor and the push service, so the tests run with no internet. On the laptop, Aziz is a simulator that never gets tired. The installation is done only when each line of a short list can be checked. The decisions are written and accepted. The contracts of both gateways are published. Each failure path has a test. Audit events reach the stream, and a stand-in for the bank's monitoring reads them. The code has a review, and the release has an independent security review and a penetration test. The guides for the app teams and for the people who run the platform exist. The full acceptance run passes in stage, against the simulators and the MyID test identities. And the product manager signs off after a demo on real phones in the test zone. Now suppose that a test identity tries to reach the production zone. What happens? Nothing gets in: production talks only to the real MyID, and its database refuses any customer with the test mark. Now walk Aziz's journey one last time. On a Sunday he registered with his number, a code through TAF and a password, and reached level one. On a Saturday he wanted to send money to his mother. He gave his consent and passed MyID, and TAF confirmed that his number was his own: level two. His phone became his one money phone. He logged out because of his nephew, and logged in again on the same phone, with his password and a code. When he lost the phone, one operator blocked it, and a second operator approved the unblock. Months later, the audit answered his letter. Each of those steps runs inside one bank, in one installation, on one host in each zone. Prove once, then bind: that is heeyID. The next module adds the one step that Aziz still cannot take alone: a new phone.
