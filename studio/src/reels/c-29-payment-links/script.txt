Wednesday, eleven at night. One of Malika's regular customers writes to her in a messenger: a birthday bouquet, delivered tomorrow at noon, can I pay now? They agree on the price in the chat. And many sellers like her have no shop site at all, and no Bekzod to build one. In lesson twenty-six, Bekzod's server created a payment and the buyer paid on the bank's page, and in lesson twenty-one, each website got its own limits. This lesson gives the same page to a seller with no website code at all. Writing a server, sealing requests and managing retries is out of reach for most small sellers. Sending a link in a chat is easy. But the link still has to be safe. It must open the real bank page. It must belong to a website the bank has checked. It must work only for a while. And its secret must not be readable from the bank's records. That is a payment link. A merchant admin or operator makes one in the merchant portal. They pick one of the merchant's live websites. They write the amount, what the buyer pays for, and how long the link works. Behind the link is an ordinary payment. It simply has no API client, because no server created it. And it has no return address, because there is no shop page to go back to. Everything else is the same. The website's own limits still apply. The website's fee still applies. The link is the bank's page address with a one-time page token, just like the link Bekzod's server receives. The bank keeps only a fingerprint of that token. So the full link is shown once, at the moment it is made. The merchant chooses how long it works, up to the bank's chosen maximum. The buyer pays on the same bank page as any other payment, with the same card frame. And a link nobody pays in time is closed as expired. I like this feature because it adds almost nothing new. A link is just a payment without a server, and every old rule still guards it. In the merchant portal, she opens payment links. The page says it plainly: sell in a chat, and send a buyer a link to the bank's payment page. She presses new link. The form asks for a live website. If none of her websites took payments yet, the form would say so, and nothing could be made. She picks her website, types what the buyer pays for, and the amount. She chooses how many hours the link works. Ask for longer than the bank allows, and the bank refuses it. She presses create. A window says your link is ready. It explains that the link is shown only once, and the bank keeps only its fingerprint. She presses copy link, and it says copied. She pastes it into the chat. Back on the list, the new link waits for the buyer, without its address. A teammate who only views can see this list, but has no new link button. Now the buyer taps the link in the chat. The same secure bank page opens, with the website, what it is for, and the amount. The buyer pays through the card frame, and the page says paid. There is no back to the shop link, because there is no shop page. In Malika's portal, the link now shows paid. Another link is never paid. It turns expired, and a buyer who opens it sees that the link has expired. So a seller without a website gets the same safe page as everyone else. The card never touches the chat or Malika. A leaked copy of the bank's records holds no working links. And the website's limits still guard every link, so a link cannot become a back door. Next: giving money back.
