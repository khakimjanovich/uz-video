How does a seller with no website take a card payment? Many small sellers take orders in a messenger. A buyer writes, the seller answers, and they agree on a price. The seller has no checkout and no website code. Writing a server, sealing requests and managing retries is out of reach. But sending a link in a chat is easy. The link still has to be safe. It must open the real bank page. It must belong to a website the bank has checked. It must work only for a while. And its secret must not be readable from the bank's records. Think of a paper bill with a pay here button printed on it. The seller writes the amount and what it is for, and hands it over. The buyer presses the button and pays. A payment link is that bill. A merchant admin or operator makes one in the merchant portal. They pick one of the merchant's live websites. They write the amount, what the buyer pays for, and how long the link works. Behind the link is an ordinary payment. It simply has no API client, because no server created it. And it has no return address, because there is no shop page to go back to. Everything else is the same. The website's own limits still apply. The website's fee still applies. The link is the bank's page address with a one-time page token, just like the link a merchant's server receives. The bank keeps only a fingerprint of that token. So the full link is shown once, at the moment it is made. The merchant chooses how long it works, up to the bank's chosen maximum. The buyer pays on the same bank page as any other payment, with the same card frame. And a link nobody pays in time is closed as expired. Now watch the product. In the merchant portal, open payment links. The page says it plainly: sell in a chat, and send a buyer a link to the bank's payment page. Press new link. The form asks for a live website. If none of the merchant's websites takes payments yet, the form says so, and nothing can be made. Pick a website, type what the buyer pays for, and the amount. Choose how many hours the link works. Ask for longer than the bank allows, and the bank refuses it. Press create. A window says your link is ready. It explains that the link is shown only once, and the bank keeps only its fingerprint. Press copy link, and it says copied. Paste it into the chat. Back on the list, the new link waits for the buyer, without its address. A teammate who only views can see this list, but has no new link button. Now switch to the buyer. The buyer taps the link in the chat. The same secure bank page opens, with the website, what it is for, and the amount. The buyer pays through the card frame, and the page says paid. There is no back to the shop link, because there is no shop page. In the portal, the link now shows paid. Leave another link unpaid past its time. It turns expired, and a buyer who opens it sees that the link has expired. What does this protect? It gives sellers without a website the same safe page as everyone else. The card never touches the chat or the seller. A leaked copy of the bank's records holds no working links. And the website's limits still guard every link, so a link cannot become a back door. So back to the bill. A bill with a button, and the same bank page behind it. Next: giving money back.
