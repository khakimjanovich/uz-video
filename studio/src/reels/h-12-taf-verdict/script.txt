Monday, ten in the morning. Aziz sits in a café, on the café Wi-Fi, and logs in to the mobile bank. He types the code from the SMS. It is the right code, and still the app says: We cannot complete this now. Why would a platform refuse a correct code? In lesson eleven, the counters guarded the code itself: its life, its tries, its requests. This lesson adds the check that no counter can do. TAF looks at where the code arrived. And it does this only in the master app. First, what TAF is. It is a state service of the mobile operators, and its agent already runs in the bank's network. In the master app, TAF sends every code for a registration and a login. Its part inside the app checks that the SMS arrived on this phone, with this SIM card. Then TAF gives a verdict. I think the most important word in this lesson is recommendation. The verdict is advice. The platform makes the decision, with the policy of the bank. The app has a job too. It starts the TAF part after an install. It sends the id of that part with each code request. It gives each typed code to the TAF part first. And it tells the TAF part at each logout. If the app skips a step, the verdict simply comes back negative. After a correct code, the platform asks TAF for two verdicts. The basic verdict is seven plain answers: the account is active, the code is usable, the SMS was sent, the status is valid, the code was verified, the device and the SIM card match, and the phone is not a clone. The risk verdict is a colour: Green, Yellow or Red, with a main reason. The risk verdict can take a moment, so the platform asks again at a set interval, until the configured waiting time ends. If it is still not ready, the basic verdict decides. All seven answers true means Green. One false answer means Red. Back to the café. The risk verdict did not arrive in time. On the café Wi-Fi, the device and the SIM card did not match, so the basic verdict said Red. Red means refuse. The login attempt ends. But a refusal blocks nothing, and it changes no counter. The app shows one piece of advice: use the mobile network of your operator, not Wi-Fi. Aziz switches off the Wi-Fi and tries again. This time the verdict is Green. The login continues, and his session in the master app gets the stronger rank, which lesson twenty-nine explains. Yellow is the careful colour. For a customer who was ever at level two, Yellow means: show the consent screen, and then a MyID re-check on this device. If his face passes, the device becomes trusted and the session gets the stronger rank. If it fails, the platform refuses. For anyone else, and that includes every new registration, Yellow means refuse, with the reason text of TAF, in the language of the journey. There is no MyID to fall back on yet. Now fast forward. Aziz is at level two, and he logs in with a Green verdict. The app asks for one more thing: the face biometric of his own phone. This is not MyID, and it gives no level. When it succeeds, the platform sends a face confirmation to TAF, with his personal identification number and his phone number. The platform sends it, never the app, so the personal identification number never reaches the phone. If TAF fails to answer, the login still continues, and the confirmation waits for the next login. For a customer at level one, there is no face confirmation at all. What if TAF is down? The platform checks its health at a set interval, and each call has a timeout. When TAF does not answer, the bank's SMS service sends the code. The attempt is marked not scored. There is no verdict, no face confirmation and no ownership check. The platform writes an audit event, tells the bank's antifraud system, and alerts operations. The session keeps the weaker rank, until a later Green raises it. When TAF is back, the next code goes through TAF again. And one case where the platform must not fall back. On the state services portal, a person can choose one trusted bank. If Aziz once chose a different bank, TAF refuses to send the code. That is not an outage. The platform stops, and it sends no code through any other channel. The app tells Aziz to change the setting there, or to contact the bank. Last, what TAF receives. The phone number, a request id, the code, the type of message, the device model and the language. The personal identification number goes only for the face confirmation, and for the phone ownership check in lesson eighteen. Never a name, a document, an address or a photo. To recap. In the master app, TAF sends the code and gives a verdict. The platform decides: Green continues, Yellow asks for MyID or refuses, Red refuses. When TAF is down, the code still comes, but not scored. When the customer chose another bank, nothing comes. But every one of these logins began before any code, with a password.
