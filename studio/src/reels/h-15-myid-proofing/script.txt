Aziz is in a lift, between the fourth and the fifth floor, when his phone loses the network. One second earlier, MyID finished the check of his face. So did the check pass, or did it vanish? In lesson fourteen, Aziz accepted the consent screen, and the platform wrote an acceptance record that permits one session at MyID. This lesson follows that one session: who opens it, what travels back to the platform, and what happens when something goes wrong on the way. Start one step earlier, in the marketplace app. Aziz wants to pay for a laptop in instalments, and the instalments need level two. The marketplace asks the platform for a step-up. The platform never refuses a step-up, but its answer to a side app is an instruction: continue in the mobile bank. If the marketplace still asks for a proofing session, it gets an error, and no session opens. Why this rule? The mobile bank is the master app: it moves money, and the bank's team adds the MyID package to it, and to no other app. Only one app holds the camera that checks faces against state records, so only one app must be defended. I think this is the right trade: one more tap for Aziz, and one door for an attacker instead of one in every app. So Aziz opens the mobile bank, and accepts the consent there. Now the backend opens the session, not the app. The platform calls MyID with the credentials of the installation, which never go to the phone. It sends the threshold of the bank: the minimum face match that MyID must apply. It gets back a session identifier, and gives a handle to the mobile bank on this same device. This is the proofing session, and it is now Open. It belongs to one customer, one device and one purpose, here a step-up, so it is a full proofing. It lives for ten minutes, a value that MyID sets. While it is open, no second session can open for Aziz. Inside the mobile bank, the MyID screen captures his document and his face. MyID checks that the face is live, and compares the face and the document with the state records. Then it gives the app one thing: a one-time result code. The result code is not the result. It is a ticket that only the platform can exchange, within five minutes, one time. The app sends the code and the session identifier to the platform. The platform accepts the code only from the device and the customer of the session, only while the session is Open, and only once. Then it calls MyID, exchanges the code, and gets the result. Now imagine that the code was copied on the way. Someone sends it again, from a different phone. The platform refuses it: wrong device, or code already used. It writes a security event. And it never stores the result code, so there is nothing to steal later. On success, the platform checks every field before it keeps it. The personal identification number must have fourteen digits. A document with an expiry date in the past is a failure, even when MyID says success. A face match below the bank's own minimum is a failure too: face not matched. Then the verified identity is kept, and the session is Succeeded. Aziz sees his names, his date of birth, the last four characters of his document number, and the first two and last two digits of his personal identification number, and he confirms them. Failures get plain words. On Aziz's first try, a lamp makes a glare on his document. MyID gives a reason code, the platform turns it into a reason key, poor image, and Aziz reads: try again now, without the glare. He never sees a code or a provider name. A failure that the person or the capture caused is counted against the limits of lesson eleven. A failure that the service caused is not counted. When MyID is down, Aziz reads that the service is temporarily not available, his level does not move, and he can try again later. There is no deferred proofing. And the lift? When the network comes back, the app reports that the check is complete, but no code reached the platform. The platform waits until MyID closes the session, and then asks MyID for the session status. A code is there, so the exchange continues, and the check did not vanish. If no code had been there, the attempt would not count, and Aziz could simply try again. To recap: only the master app runs MyID, the platform opens the session with credentials that stay in the bank, the app carries back a one-use code, and every failure has a key, a counting rule and plain words. Aziz is now at level two. Next year, he buys a new phone. Must he show his passport to MyID again? Next: prove once.
