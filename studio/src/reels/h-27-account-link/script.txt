Last spring, Aziz bought a phone case on the marketplace website. He typed his number, an SMS code, and a password. Today, his friend shows him the mobile bank, and Aziz installs it for the first time. So now one number has two doors: a web account that only an SMS code ever checked, and the mobile bank, which is about to check the SIM card itself. Should the mobile bank simply trust that old web account? In lesson twenty-six, a new customer on the marketplace website got an app account marked not confirmed. This lesson removes that mark, in the mobile bank, right after the TAF check. First, why the mark exists. An SMS code on the web proves one small thing: someone read a message to this number, at that moment. It says nothing about the phone, or the SIM card, or who was holding it. A browser cannot run the TAF part, so nothing better was possible there. Now Aziz types his number in the mobile bank. The platform sees that this number already has a customer. So this is not a new registration, and the mobile bank does not make a second customer. It asks for the password that this number already has. Aziz types it. Then TAF sends a one-time code to his number, and checks that it lands on this phone, with this SIM card. The verdict is green. Only now, after a correct code and a green verdict, does the platform look at the marketplace. It finds an app account of this person in the marketplace, still marked not confirmed. So the mobile bank asks one question. This number also has a marketplace account. Is it yours? Link it? Aziz remembers the phone case, and he taps Yes. The marketplace account stays as it is. Its mark changes to linked, verified through the mobile bank. From now on, it uses the level of the person, so when Aziz is at level two, the marketplace sees level two too. That was the easy answer. Now suppose Aziz had never used the marketplace at all. Someone else typed his number on the website, long before he did. That person read one SMS code to his number, and set a password. So Aziz taps No. The mobile bank does not act at once. It asks a second time: This ends all marketplace sessions and closes that account. Continue? There is a Back button. Back changes nothing, and the question stays. I think this second question is right. One wrong tap on No would log the real owner out of every marketplace browser, so the app makes him say it twice. Aziz taps Continue. The platform ends every marketplace session of this number, on every browser and phone. The marketplace account is closed. It is not deleted. A bank operator can open it again, with a reason, during the retention period. A later login in the marketplace makes a new app account, on a clean page. Then the mobile bank asks Aziz to change his password at once. Why? Because the person who made the web account may know it. But look at that again. If someone else made the web account, Aziz did not know its password in the first place. So he could not even pass the first step in the mobile bank. What does he do then? He resets the password in the mobile bank. The reset uses the same TAF check, and the mobile bank offers a MyID check in the reset. Aziz was never at level two, so it is a full MyID check, with his consent. With a green verdict and MyID, the reset does not wait. Lesson thirty explains the waiting reset. And the new master-app session that comes out of the reset outranks every marketplace session. So the reset itself ends all of the stranger's marketplace sessions. Lesson twenty-nine explains that rank. One more rule: each answer writes an audit event and sends an event to the bank's antifraud system. So the bank can see later who linked what, and who refused. To recap: an account that only an SMS code checked stays not confirmed. After a correct code and a green TAF verdict in the mobile bank, the customer answers one question. Yes links the account. No, then Continue, ends its sessions and closes it, without deleting it, and the password changes at once. Aziz said Yes. His marketplace account is linked, and a week later he passes MyID and is at level two. Now the marketplace wants to deliver his next order, and it needs his address. The platform keeps his registered address, from MyID. Can the marketplace simply read it? Next: address sharing.
