Where does a payment system start, if not with payments? It starts with a project that builds, and an environment that runs with one command. We use Java twenty-five and Spring Boot four, built by one Gradle build with a module for each part of the domain. The app has five modules, partner, commission, terminal, card, and payment, and each one owns its own schema, with a database user that can see nothing else. A boundary test fails the build if one module reaches into another module's code or tables. Every version is pinned in one catalog file, so the build is the same on every machine. A separate infrastructure repository uses Docker Compose to start Postgres, Redis, and Keycloak, and nothing else yet. Every other tool joins only in the episode whose problem needs it. With one setting, the app logs structured JSON in the community ECS format, and reports its health from the very first minute. One command in the infrastructure repository, and the whole world is up.
