Where does a payment system start, if not with payments? With a stack, a build, and an environment that runs with one command. We chose Java twenty-five and Spring Boot four: long-term support, and the most widely used stack for Java services. We chose Gradle, with builds in Groovy, because the build is the pipeline: it generates code from the contracts, checks the style, and runs the tests, the same way on every machine. The app is one modular monolith with six modules, partner, commission, e POS, BIN, card, and payment: one deploy today, and clean seams for tomorrow. Each module owns its own schema in one database, and connects as its own user, which can see that schema and nothing else. A module asks another only through that module's contract, the internal operations in its OpenAPI file, and the build fails if it reaches any further. Inside, every module uses the one layout every Spring developer knows: layered, with a controller, a service, a repository, and an entity. We chose contract first: an OpenAPI file comes before any code, Gradle generates the interfaces and models, and the code must implement them, so it never drifts from what clients were promised. The same contract generates a client interface too: one module calls another through it inside the app today, and over HTTP the day that module becomes its own service. Shared pieces, the error format, security, persistence, crypto, Vault, observability, and every contract, live in the platform folder, as one Gradle build of libraries. The app and each adapter include that build, a Gradle composite build, so the libraries are built from source and nothing is published. One version catalog in the platform pins every version, and the app and both adapters read that same file. Errors follow one format, R F C ninety-four fifty-seven problem details: each module lists its errors once, and every failure answers with a stable code, the request's id, and a message in English, Russian or Uzbek. Services that do one job live outside the app, each with its own contract and client: the card scheme adapters. One infrastructure repository starts all of it with one Docker Compose command, and each piece is explained in the episode that first uses it. Every secret, from each module's database password to the card keys, comes from Vault at startup, and the app does not start without it. Next, the domain, which comes before a single table.
