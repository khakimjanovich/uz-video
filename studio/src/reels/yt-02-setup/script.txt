Where does a payment system start, if not with payments? It starts with a project that builds, and an environment that runs with one command. We use Java twenty-five and Spring Boot four, built by one Gradle build with a module for each part of the domain. The app has five modules, partner, commission, terminal, card, and payment, and each one owns its own database schema. A boundary test fails the build if one module reaches into another module's code or tables. Every version is pinned in one catalog file, so the build is the same on every machine. Docker Compose starts Postgres, Redis, and Keycloak, and nothing else yet. Every other tool joins only in the episode whose problem needs it. The app logs in JSON and reports its health, so we can see it from the very first minute. One command, and the whole world is up. Next, we design the domain before we write a single table.
