What stops one admin from switching on a fraudulent shop? If one person could do it, one mistake or one bribe would be enough. So activation is a request: one admin, the maker, asks, and nothing changes yet. There is no single-admin activate call: one call opens a request, and others list, approve, and reject requests. A different admin, the checker, approves it, and only then does the merchant become active. A request is decided once: it must still be pending, not expired, and the checker can't be the maker. Self-approval answers four oh nine, with its own error code. Both opening and approving a request check again that every required company document is verified. The checker's name goes into the status history, with the maker in the reason. Requests expire after a configured time, twenty-four hours here. A scheduled sweep marks overdue requests as expired, and ShedLock makes sure only one instance runs it. Only one pending request per merchant can exist, and a partial unique index in the database enforces it. Next, real logins with Keycloak, so every admin action carries a verified name.
