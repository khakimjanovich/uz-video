What stops one admin from switching on a fraudulent shop? If one person can do it, one mistake or one bribe is enough. So activation becomes a request: a maker creates it, and nothing changes yet. A different admin, the checker, approves it, and only then does the merchant become active. The maker can never approve their own request. A request that waits too long expires after the configured time. A scheduled sweep marks old requests as expired, and a lock makes sure it runs only once. Only one pending request per merchant can exist, enforced by a unique index in the database. Next, logins and API keys, without storing a single password ourselves.
