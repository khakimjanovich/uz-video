How does our system talk to Uzcard and Humo, when they speak different languages? Uzcard speaks JSON-RPC, and Humo speaks SOAP, with different fields and different errors. If the payment code knew both, every new scheme would mean touching payment code. So the card module defines one port, a card processor: bind a card, debit, reverse, and status. Each scheme gets its own adapter behind that port. Uzcard debits in one step, by the card's token, with our payment id as the external reference. Humo holds the money first, then captures the hold right away. Every answer becomes one of three outcomes: approved, declined with our own code, or unknown. A timeout is unknown and never a decline, because the money may already have moved. If we retry a payment the scheme already has, we look it up instead of paying twice. A processing sandbox in the infrastructure repository stands in for both schemes, with a test card for every outcome. Integration tests send real HTTP to that sandbox, including a payment that never answers. Next, knowing a card's scheme, and storing its number safely.
