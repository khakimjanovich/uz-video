How does our system talk to Uzcard and Humo, when they speak different languages? Uzcard speaks REST, and Humo speaks SOAP, with different fields and different errors. If the payment module knew both, every new scheme would mean touching payment code. So we define one port, a card processor, with a few commands: one-time code, authorize, capture, reverse, and status. Each scheme gets its own adapter behind that port. The payment module sends the same command, whatever the card. Each adapter translates the scheme's errors into our own codes, so a decline looks the same everywhere. We demo every command against the schemes' test environments. Next, knowing a card's scheme, and storing its number safely.
