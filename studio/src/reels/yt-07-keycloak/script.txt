Who is calling our API, and how do we know? Until now, an admin was just a name in a header, and anyone can type a header. Keycloak now holds every login: the bank's admins, the merchants, and the merchants' servers. The realm defines two roles, admin and partner, and a client the backend uses for itself. Signing up now takes a password, which goes straight to Keycloak and never into our database. The new login can do nothing until the email is verified, and then it gets the partner role. Every request now carries a token, and the app checks it before any business code runs. Admin routes need the admin role, partner routes need the partner role, and anything not listed is refused. The admin's name now comes from the token, so the history shows who really acted. An active merchant creates API clients for its servers, and each secret is shown only once. Rotating issues a new secret, and the old one stops working at once. One integration test runs the whole onboarding on a real Postgres, Redis, Mailpit, and Keycloak. Under load, every scenario passed with real tokens, from sign-ups to secret rotation. Next, the websites that will actually take the payments.
