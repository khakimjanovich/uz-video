Saturday afternoon. Aziz is at his parents' house, and his mother wants a new washing machine, paid in parts. He opens the marketplace website on her old laptop. This browser has never seen him. It cannot check his face, and it cannot check his SIM card. So how does a website that knows nothing about this laptop trust that it is really Aziz? In lesson twenty-four, Aziz logged in on a new phone in the mobile bank: the TAF code, then an approval on his trusted phone. This lesson takes the same idea to the side apps, where there is no TAF and no MyID. First, what a side app cannot do. A browser cannot run the TAF part, so there is no verdict and no face confirmation. A side app never opens MyID, and it does not detect remote access. All of that lives only in the master app, the mobile bank. So a side app has the password and the bank's own SMS service. And it has one more tool, the best one: the master app itself. Start with a customer who is new. On the website, a new customer types the phone number. The bank's SMS service sends a one-time code. The customer types the code, then a password, two times. The platform makes a customer at level one, a device record for the browser, and a marketplace app account with one session. The browser is never a trusted device. And the new app account is marked not confirmed. It stays so until a TAF check in the mobile bank. Hold on to that mark: the next lesson is about it. Aziz is not new. He types his number and his password. The password always comes first. No code goes out, and no request goes anywhere, before the password is correct. Now the platform looks for a session of Aziz in the master app. He has one, on his phone. So the platform sends no code at all. It makes an approval request instead, and sends a push signal to the mobile bank. The push carries only the request identifier. The mobile bank pulls the request over its own session, and shows it to Aziz. It shows the marketplace, the browser, the network address, the time, and a warning never to give a code to anyone. Two buttons: Approve, and This was not me. Aziz taps Approve. The laptop session starts, and it gets the level of the session that approved it. Aziz passed MyID long ago, on this trusted phone, so the laptop session is at level two. That is the only way a side-app session reaches level two: an approval in the master app, from a customer at level two. I think this is the strongest part of the design. The approval travels over a session that the bank already trusts. And it carries no code, so nobody can phone Aziz and ask him to read one out. Now the other paths. Suppose Aziz misses the request. It waits for the configured time. Then the bank's SMS service sends a one-time code to his number. The code alone is enough, but the session is only at level one. A customer with no session in the master app gets the same: a code by SMS, and level one. And if Aziz taps This was not me? Someone knows his password, so his number goes on hold. Lesson thirty-one follows that path. The marketplace app on a new phone works the same way. When Aziz has a master-app session that passed the TAF check, the approval replaces the SMS code. Without one, the bank's SMS service sends a code, and the session starts at level one. Note what a side app never does at login: it never asks for MyID. Even for a customer who was at level two, a new phone or a long pause gives a side-app session at level one. Level two comes only after the approval. After each login, Aziz gets a notification by push and by SMS: a new web login, with the time and the browser. Back to the washing machine. Paying in parts needs level two, and the credit service reads the level of this session. With a session at level one, the marketplace would not open MyID. It would send Aziz to the mobile bank, because MyID runs only there. To recap: a side app asks for the password first. Then an approval in the master app replaces the code, or the bank's SMS service sends one. Only the approval can give level two. But remember the mark on a web account: not confirmed. Many customers make a marketplace account on the web before they ever install the mobile bank. When the same number arrives in the mobile bank, was that web account really made by this person?
