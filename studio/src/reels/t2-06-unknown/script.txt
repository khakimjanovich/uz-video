The processing center never answered: was the money taken or not? The simplest way is to send the debit again. But if the first debit did go through, the retry charges the buyer twice. So a timeout is treated as an unknown outcome, and the payment stays authorizing. A durable workflow, built on Temporal, asks the processing center for the status on a configured retry schedule. If the money was taken, the payment is captured, and if nothing happened, it is declined. If there is still no clear answer within the configured time limit, the payment goes to a manual review queue. A scheduled sweep also picks up any payment left stuck, so nothing is forgotten.
