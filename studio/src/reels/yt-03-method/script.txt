Where do you start designing a feature: the database, the API, or the code? We start with the domain: the things that exist, the states they move through, and the rules that never break. First comes a one-page sketch of the whole system: the main entities, and which module owns each one. Links between modules are only IDs, never foreign keys, so a module can move out on its own later. Second comes the contract: an OpenAPI spec that promises outsiders exactly what they can ask for. Gradle generates the API interfaces from it, and our controllers must implement them, so the code can never drift from the spec. Third comes the database: a Liquibase migration in the module's own schema. Then we write the smallest code that keeps the rule, and one test that fails if the rule breaks. Domain, contract, database, code, and test: every episode follows this order. Next, the first real feature: a merchant signs up and proves they own their email.
