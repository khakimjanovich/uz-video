Go back to the first day of this journey. It is a Sunday, in Aziz's first week, and he installs the mobile bank on his one phone. All he has is a phone number. So how does a phone number become an account that the bank can trust? Lesson seven gave the apps a contract, with one call for each step. This lesson follows the first of those calls: the registration, from a phone number to level one. The app opens with two buttons: Register, and Log in. On the login screen, a link leads to the registration, and its text is always the same. That text never depends on the number, so the screen tells nobody if a number already has an account. Aziz taps Register. First, the app shows the terms and the privacy text, in his language. The text names TAF, the antifraud service of the mobile operators, as a receiver of his phone number and his phone model. Aziz accepts. Then he types his number and taps Continue. The app sends one request: the number, the language, the version of the terms that Aziz accepted, and a short description of the phone. The description is the platform, the model, the system version and the app version. The request also carries its network address. The platform checks four facts. The number is a real mobile number of Uzbekistan. The app is active. The terms version is the current one for his language, and the platform records his acceptance. And no limit is reached, which lesson nine shows. Now the platform opens a registration record, in the state Started. From now on, every text and every code message to Aziz is in his language. The platform also gives the app a device identifier, and keeps it on the record. Only this phone can continue this registration. Then the platform makes a one-time code. It is random, and it never comes from the number, the time or the phone. The platform keeps only a fingerprint of the code, so even the database cannot say the code back. The app gets the lifetime of the code and the number of resends that remain, but never the code itself. The mobile bank is the master app, so TAF sends the SMS. Its part inside the app checks that the code arrived on this phone, with this SIM card. If TAF does not answer, the SMS vendor sends the code instead, and lesson ten shows what that changes. Today the SMS is slow. After a minute, Aziz goes back and taps Register again. A second registration for the same number ends the open one, and its code is void. So one number has only one open registration at a time. Then two messages arrive, and only the code in the second one is alive. Aziz types it. The platform takes a code only from the phone that started the registration. A code from another device counts as a wrong entry, even when it is right. Here the phone is the same, and the fingerprints match. The record moves to Number verified, and the code is void. Then TAF gives its verdict, and today it is Green; lesson ten explains the colours. Only after the verdict does the platform look up the number. It belongs to nobody, so Aziz is a new person. Until the number is verified, the platform makes nothing for it: no consent, no device record, no session. Now the app asks for a password. Then the phone rings, and Aziz's mother talks for ten minutes. In the background, the phone closes the app. When Aziz opens it again, the app asks the platform for the state of its registration. The answer is Number verified, so the app opens the password screen again, not the start. Only the phone that started the registration gets this answer; any other device gets the state Expired. Aziz types a password, and then the same password a second time. The two entries differ by one letter, and the platform refuses. He types them again, and now they match. The rules for a good password, and how the platform keeps it, are in lesson eleven. Now four things appear at once. A customer at level one. An app account in the mobile bank. A device record for his phone, known, but not yet trusted. And a session for this phone. The registration record is now Onboarded. The platform sends the message registration complete as an SMS at once. A push follows when the phone gives its push token to the platform. A registration that never reaches level one does not wait forever. After the configured time, the record expires. The platform deletes its data and keeps only the audit events. A new try starts from the beginning. Now take the slow SMS again, and suppose that Aziz types the code from the first message. Does it work? No: the second registration ended the first one, so only the newest code is alive, and the old code counts as a wrong entry. Two entries, and a link that never depends on the number. The terms first, then one request, four checks and a registration record. A code through TAF, taken only from the phone that started. One open registration for each number, and a restart that continues where it stopped. A password two times, then level one, and a message that says so. The code that Aziz typed lives on only as a fingerprint, and lesson nine shows the limits around it: its lifetime, its tries and the cool-downs.
