Can a merchant jump straight from signing up to taking payments? Without rules, one wrong update could switch on a shop nobody ever checked. So a partner moves through fixed states: pending, verified, waiting for a contract, approved, and active. The allowed moves live in one table inside the status enum, and every other move is refused. An illegal jump, like pending straight to active, answers four oh nine with a stable error code. Before the bank approves a company, the merchant uploads its company documents: the charter and the director's passport. The files go to a separate file service, which reads each file's type from its own bytes, checks its size, and stores it in an S3 bucket. The partner module keeps only the file id, type, size and checksum, and an older upload of the same type is kept as replaced. An admin opens each document and verifies it, or rejects it with a reason the merchant can read. The admin approves the company only after its email is verified and every required document is verified; the configuration lists which ones. Signing the contract approves the partner, and the database keeps every contract number unique. Every change writes a row to the status history: from where, to where, who, and why. Each row is saved in the same transaction as the change, and is never updated. An active merchant can be suspended and restored, or terminated for good. Activating and restoring both end in active, so each one is allowed only from its own starting state. Next, we make sure no single admin can switch a merchant on alone.
