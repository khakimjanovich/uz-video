How do we know whether a card is Uzcard or Humo, which bank issued it, and where do we keep its number? A card's first digits, its BIN, name the scheme and the bank. Both schemes publish their BIN lists, so the BIN module syncs them through the adapters into its own schema, at startup and every night. The sync is idempotent, and a scheme that doesn't answer, or answers with nothing, keeps its old list. Lookups never touch the database: an in-memory index cuts the digits, even a full card number, from the longest known BIN length down to the shortest, and the first match wins. A bank directory in the configuration names the issuing bank in English, Russian and Uzbek. Before any scheme is asked, the card module checks the Luhn digit, then asks the BIN module for the scheme. A plain card number in our database would be a disaster on the day of a breach. So the crypto platform library seals the number with AES two fifty six GCM: a fresh nonce every time, and the key id is authenticated with it. Each value names its key, so a new key can take over while older data still reads. Other modules get a card token instead, and the same card always gets the same token. To find a card without decrypting anything, we also store a keyed hash of its number, a blind index. The database itself refuses a card number stored in plain text. A number is decrypted only to hand it to the card's scheme, and every use is written to an audit trail. The bank's console shows each range with its bank, and finds a card by its number without ever showing that number. Next, the payment itself, starting with a request nobody can forge.
