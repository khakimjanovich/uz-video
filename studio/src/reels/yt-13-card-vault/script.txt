How do we know whether a card is Uzcard or Humo, and where do we keep its number? A card's first digits, its BIN, name the scheme. Both schemes publish their BIN lists, so the card module syncs them into a registry, at startup and every night. The sync is idempotent, and a scheme that doesn't answer, or answers with nothing, keeps its old list. The longest matching prefix wins, so a bank's eight digit range beats the scheme's six digit one. Before any of that, the Luhn check digit catches a mistyped number, and it caught some sandbox test cards that were never valid card numbers. A plain card number in our database would be a disaster on the day of a breach. So a new platform library, crypto, seals the number with AES two fifty six GCM: a fresh nonce every time, and the key id is authenticated with it. Each value names its key, so a new key can take over while older data still reads. Other modules get a card token instead, and the same card always gets the same token. To find a card without decrypting anything, we also store a keyed hash of its number, a blind index. The database itself refuses a card number stored in plain text. A number is decrypted only to hand it to the card's scheme, and every use is written to an audit trail. Integration tests read the stored row back and find no card number in it. The bank's console shows the registry and finds a card by its number, without ever showing that number. Next, the payment itself, starting with a request nobody can forge.
