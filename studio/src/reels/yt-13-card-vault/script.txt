Where does a card number live, and how does the rest of the bank use a card without ever seeing it? A card's first digits, its BIN, name the scheme and the issuing bank. Both schemes publish their BIN lists, so the BIN module in card-vault syncs them through the adapters into its own schema, at startup and every night. The sync is idempotent, and a scheme that doesn't answer, or answers with nothing, keeps its old list. A range the schemes' lists don't carry yet can be added by hand, and no sync removes it. Lookups never touch the database: an in-memory index cuts a card's first digits from the longest known BIN length down to the shortest, and the first match wins. A bank directory in the configuration names each issuer in English, Russian and Uzbek, and without it card-vault doesn't start. Before any scheme is asked, the card module checks the Luhn digit, then asks the BIN module for the scheme, sending only the first eight digits. A plain card number in a database would be a disaster on the day of a breach. So card numbers live in one place only: card-vault, in the separate cards unit, with its own Vault, Keycloak and Postgres. Other units hold a card token instead and call card-vault over mutual T L S, where each operation needs its own role: bind, read, debit, reports or admin. Card data is sealed by Vault Transit: card-vault sends a value in and keeps only the ciphertext, so the keys never leave Vault. Each value is sealed with a context naming its column and its card, so a ciphertext copied to another row doesn't open. Rotation is Vault's own: new values take the new key version, older ones still open, and a rewrap moves them forward. To find a card without decrypting anything, the vault keeps a blind index, a Transit HMAC of the number, pinned to one key version so the same number always gives the same index. When Vault is down or refuses, card-vault fails closed with card processor unavailable, and never guesses. The database itself refuses any card value that isn't a Vault ciphertext. A number is decrypted only to hand it to the card's scheme, and every use of card data is written to an audit trail. Bank admins reach cards and the BIN directory only through the API, with the cards admin role, and a search by number answers only the masked number.
