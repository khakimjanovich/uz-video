The buyer changed their mind: how does the money go back to the card? There are two ways, and the day decides: before the scheme settles the day's payments, or after. On the day it was paid, the debit is reversed: Uzcard reverses the transaction, and Humo cancels it, as if it never happened. Later, it is refunded: Uzcard reverses it all the same, and Humo returns the payment. Which day it is, is read in the settlement time zone, Tashkent, from configuration. A refund is allowed only within the website's refund window, set when the bank switched it on. Both schemes give back the whole payment, so the whole amount goes back, never a part. One conditional update claims it: paid becomes returning, and only one caller wins. The operation is written to the journal before the scheme is asked, with the scheme's own id for the debit. Approved is final, reversed or refunded; refused leaves it paid; and no answer leaves it returning for a person, never sent twice. Like every ending, it raises an event, so the merchant's webhook hears about it. The merchant's server asks with a signed request; for a payment link, the merchant's user presses give back in the portal. Next, the bank's own side of the money: billing and reports.
