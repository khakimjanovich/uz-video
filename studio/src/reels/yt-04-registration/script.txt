How do we know a new merchant really owns the email they typed? Anyone can type any address, so a sign-up alone proves nothing. The contract adds three calls: register, verify the email, and resend the code. Registering saves the merchant as pending, and refuses an email that is already taken. A one-time code then goes to that email, from a new OTP starter that any module can use. Redis keeps only a hash of the code, with a configured lifetime, so even a copy of Redis never reveals it. The email goes out through the notification service, and locally it lands in Mailpit, where we can read it. The merchant sends the code back, and only then is the email marked as verified. Wrong codes count against a configured limit, and too many lock the code. Sends are limited too, so nobody can flood an inbox. Every failure has its own stable code: email taken, code invalid, code expired, or too many attempts. Under load, about five thousand merchants registered and verified their email in thirty seconds. Next, the merchant moves through a lifecycle, from pending to active.
