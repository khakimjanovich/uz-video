How do you know which network a card belongs to before you ask anyone? In lesson three, the masked number kept the first six digits, because they tell which bank gave out the card. In lesson nine, the full number was sealed away. This lesson shows what those first digits tell the card zone, without opening the full number. Think of a phone number. Its first digits tell you the country. They tell you that before anyone answers. They never tell you who you are calling. And a longer code is more exact than a shorter one. A card number works the same way. Its first digits name the card network and the bank that issued the card. Those first digits are called the BIN, short for bank identification number. Each network publishes its own list of BINs: which first digits belong to which bank. That is the network's BIN list. The card zone copies those lists in through the adapters. It copies them when it starts, and again on the bank's chosen schedule. Sometimes a network does not answer, or answers with an empty list. Then the card zone keeps its old list. An old list is better than no list. A lookup works like a phone code. The card zone takes the first eight digits. It tries all eight, then seven, then six. The longest match wins, because it is the most exact. The lookup runs in memory, so it is fast and never touches the database. And the part that knows BINs only ever sees those first eight digits. It never sees the whole number. An unknown BIN is not an error. The answer is simply an empty list. Why does this matter? Before any network is asked to send a code to a buyer's phone, the card zone checks the card's network this way. A shop may accept only some networks. If the card belongs to a network the shop does not take, the card is refused right there. No network is bothered. No phone buzzes. Now watch the product. The buyer opens the bank's payment page. Above the card form, the page shows the networks this shop accepts. The buyer types a card from another network and presses "Send code". The form answers at once: "This shop doesn't accept this card. Use another card." No code is sent. Nobody's phone lights up. Next, the buyer types a card whose first digits no network has listed. The form says that no network issues cards starting with those digits. Again, nothing is sent. Then the buyer types a card the shop accepts. A code arrives on the buyer's phone. The buyer types it and confirms. The form says "Card accepted". The payment page now shows the masked number, the card's network, and the name of the bank that issued it. That bank name came from the first digits alone. On the bank's side, nothing alarming happens. A wrong-network card is a normal refusal, not an incident. The team only hears about it if the lists stop arriving. What does this protect? Without the check, the card zone would ask the wrong centre to send a code. A real person's phone would buzz for a payment that can never work. The network would carry a request it should never see. With the check, a wrong card stops at its first digits. It also protects the number itself. The part that names networks needs only the first eight digits, so that is all it gets. Back to the phone. A country code tells you where a call goes, before anyone answers, and never who picks up. A card's first digits do the same. They name the network and the bank, never the person.
