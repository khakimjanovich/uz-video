Ten past eleven at night, a buyer on Malika's site types a card and presses Send code. Malika's shop accepts only some card networks, and this card belongs to another one. The buyer's phone stays dark. No code is sent, no network is asked, and the form answers at once. How did the card zone know, before asking anyone? In lesson three, the masked number kept its first six digits, because they say who gave out the card. Tonight, those digits do the work. A card's first digits name the card network and the bank that issued the card. They are called the BIN, short for bank identification number. Each network publishes its own list of BINs: which first digits belong to which bank. That is the network's BIN list. The card zone copies those lists in through the adapters. It copies them when it starts, and again on the bank's chosen schedule. Sometimes a network does not answer, or answers with an empty list. Then the card zone keeps its old list. An old list is better than no list. The lookup is like a phone's country code, where a longer code is more exact. The card zone takes the first eight digits. It tries all eight, then seven, then six. The longest match wins. The lookup runs in memory, so it is fast and never touches the database. And the part that knows BINs only ever sees those first eight digits. It never sees the whole number. A BIN nobody has listed is not an error. The answer is simply an empty list. Now the order that matters. Before any network is asked to send a code to a buyer's phone, the card zone checks the card's network this way. If the shop does not take that network, the card is refused right there. No network is bothered. No phone buzzes. I think this is the cheapest safety in the whole system: the request you never send. Skip the check, and the card zone asks the wrong centre to send a code. A real person's phone buzzes for a payment that can never work. A network carries a request it should never see. Tonight's buyer saw all of it. Above the card form, the bank's payment page lists the networks Malika's shop accepts. The buyer typed a card from another network and pressed Send code. The form said: "This shop doesn't accept this card. Use another card." Nothing was sent. Then the buyer mistyped a number, and its first digits belonged to no listed network. The form said that no network issues cards starting with those digits. Again, nothing was sent. On the third try, the buyer used a card the shop accepts. A code arrived on the buyer's phone. The buyer typed it and confirmed, and the form said "Card accepted". The payment page showed the masked number, the card's network, and the name of the bank that issued it. That bank name came from the first digits alone. At the bank, nobody was woken. A wrong network card is a normal refusal, not an incident. Timur's team only hears about it if the lists stop arriving. Eight digits named a network and a bank, and never the person holding the card. Next: how the card form protects itself in the buyer's browser.
