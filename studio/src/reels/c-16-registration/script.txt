How do you know the person signing up really owns that email address? Lesson fifteen finished the locked room, so from here the course builds the shop's side, ecom. In lesson one, a shop's owner and staff used a portal, and the bank's staff approved shops. This lesson starts at the very beginning: how a shop signs up. Anyone can type anyone's email into a sign-up form. Picture a stranger who signs up a shop with a famous brand's address. Later the bank sends contracts, reports and payout notices to an inbox the real owner never controlled. So the bank does what a postcard with a code does. Some services mail a postcard to an address, and only someone who gets that post can read the code and type it back. Here is how it works. A person fills in the sign-up form. Their password goes straight to the login server, the one place that checks passwords. It never touches ecom's own database. ecom saves the new merchant as pending, and nothing more. Then ecom sends a one-time code to the email address. A one-time code is a short number that works once, for a short time. Only someone who can read that inbox can type it back. The store that keeps the codes never keeps the code itself, or the email. It keeps only fingerprints of them: enough to check a match, useless to anyone who steals them. When the right code comes back, that is email verification: proof that the person controls the address. Wrong guesses are counted. Too many wrong codes, and the sign-up is locked until the window ends, even if a new code is asked for. That is a lockout. Every refusal says when to try again. And if the store that keeps the codes is down, nothing is sent and nothing is accepted. The system fails closed, never open. Now watch the product. The viewer opens the merchant portal and clicks to sign up. The page says "Create a merchant account", and under it, "We will email you a code to confirm the address." There are three boxes: company name, work email and password. The viewer fills them in and clicks Create account. Now the test inbox. A new email has arrived, with a six-digit code inside. Back in the portal, the page says "Check your email." It asks for the code, and says it works for a few minutes. While the code box is not full, the Verify button stays grey. The button under it, "Send a new code", counts down the seconds before it can be pressed again, so nobody can flood an inbox. The viewer types the six digits, and the Verify button lights up. One click. The page says "Email verified", and tells the person to sign in. It also says the bank will now check their documents. Behind that screen, the person who signed up becomes the merchant's first admin, both in ecom and on the login server. What does this protect? Without it, anyone could open a merchant account in someone else's name. Contracts, reports and payout notices would go to an address the real owner never saw. The one-time code protects the real owner of the address. It protects the bank too, because every later message reaches the person who really asked. The lockout stops a stranger from guessing the code. And failing closed means a broken code store can never let an unchecked sign-up through. So, like the postcard with a code: only the inbox's owner can answer, and only the inbox's owner gets in. Next: how a merchant earns the right to take money.
