A merchant may run several websites, so which one is allowed to take payments? A sales point is one website, with the return addresses where buyers come back after paying. Every return address must be an https page on the website's own domain, so a payment can never send a buyer somewhere else. A new sales point starts as a draft, and can't take payments yet. An admin checks the website and records the result. A failed check must list what is wrong, and every check is kept. The deal sets the card schemes and the refund window, and a longer window needs a reason and stays under a configured maximum. Switching it on needs an active merchant, a passed latest check, and at least one card scheme. Once it is live, the return addresses are frozen. A live website can be suspended and restored, and a closed one stays closed. Other modules ask one question: may this sales point take a payment right now, and the answer fails closed. Unit tests cover every rule, and integration tests run the whole path on a real Postgres. Under load, about sixteen hundred websites were checked and switched on in thirty seconds. Load testing also caught two real bugs: a validator that crashed on web addresses, and a pattern that refused every https link.
