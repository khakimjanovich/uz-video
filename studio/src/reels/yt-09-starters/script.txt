What happens when the next module needs the same security and the same Keycloak calls as the first? Right now the security rules live in the app, and the Keycloak calls live inside the partner module. Copy them into a second module, and every fix must be made twice. So both become platform libraries, published like the error and OTP libraries before them. The security library secures any app: access tokens, realm roles, and refusals as problem details. The route rules move into configuration, and anything not listed is still refused. It configures itself before Spring Boot's own defaults, and an app can still replace it. The Keycloak library is a small admin client that logs in as its own client and refreshes its token. The partner module keeps its own identity port, and now simply delegates. Each library has its own tests: route rules with fake tokens, and the admin client against a real Keycloak. Nothing changed for callers: the full onboarding test and the load tests pass unchanged.
