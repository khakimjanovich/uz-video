Where does code go when more than one module needs it? Security rules and Keycloak calls are needed by every module that takes requests, not only by the partner module. Copied into each module, every fix would have to be made twice. So shared code lives in platform libraries, versioned and published, next to the error and OTP libraries. The security library secures any app: access tokens, realm roles, and refusals as problem details. Its route rules are configuration, and anything not listed is refused. It configures itself before Spring Boot's own defaults, and an app can still replace it. The Keycloak library is a small admin client that logs in as its own client and refreshes its token. The partner module keeps its own identity port, and its Keycloak adapter simply delegates to that client. A module asks the version catalog for a library by name, and gets one tested, versioned jar.
