Where does code go when more than one module needs it? Security rules and Keycloak calls are needed by every module that takes requests, not only by the partner module. Copied into each module, every fix would have to be made twice. So shared code lives in platform libraries, in one versioned platform build, next to the error and OTP libraries. The security library secures any app: access tokens, realm roles, and refusals as problem details. Its route rules are configuration, and anything not listed is refused. It configures itself before Spring Boot's own defaults, and an app can still replace it. A module adds its own filter to that one chain through a customizer, and a customizer that sets route rules stops startup. The Keycloak library is a small admin client that logs in as its own client and refreshes its token. Every call has a configured timeout, a refused token is replaced once, and each failure is a problem detail: conflict, rejected, or unavailable. The partner module keeps its own identity port, and its Keycloak adapter delegates to that client, and turns a conflict into email taken. Each library ships its own defaults and error messages, so the app configures only what differs, and secrets come from Vault. A module asks the version catalog for a library by name, and Gradle builds it from the included platform build. Next, the money rules begin, with the commission on every payment.
